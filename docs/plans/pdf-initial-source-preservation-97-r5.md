# #97 初回PDF補正：コード例は紙面の行を保持し、論理改行の復元とは区別する（第5改訂）

## 目的

読者に、初回PDF補正で読めた原文を元の位置・役割・順序で届ける。本文は実際の翻訳入力、コード例は翻訳しない英語出力で確かめる。コード例の成果物は**本に印刷された例**であって、著者が編集した実行用ソースではない。

正式入力：[Issue #97 第4改訂コメント](https://github.com/minorunakamura/doc-translate/issues/97#issuecomment-6998270720) と[第4改訂 Plan](pdf-initial-source-preservation-97-r4.md)（SHA-256: `692921304f718eb4991d73ab12e5dffab32ca0ba97d1eef559e415f530251ecd`）。本改訂は、第4改訂の「物理折返し」とコード3対照の受入条件を**下記の紙面基準に置き換える**。共通の目的は[第2改訂「目的」](pdf-initial-source-preservation-97-r2.md)から変えない。過去のPlan・固定対照は更新しない。

## 停止理由と根拠

80枚目の該当コードはDoclingでは1 ref・1行、紙面では5非空行で、第2行のみ等幅1字分右に始まる。第4行→第5行の位置は読めるが、著者がそこで改行したのか組版で折り返したのかを示す独立の根拠は確認できなかった。77・79でも同じ問題が起こり得る。77は5 refに対し固定対照9非空行、79は2 refに対し26非空行で、refの個数も論理行数の根拠にならない。

今回の私有証拠：`work/test-verification-97-r4-root-culTpOJo/{listing-shape,logical-evidence-probe,style-check,readback}.json`。確認した範囲で明示EOL・論理行を示すタグ等は検出されなかった。これは「改行がない」という証明ではない。部分実装 `pdf_adoption.py::_listing_layout` と再生helperの `listing_evidence` は、ともに紙面行が変わると最低1改行を数える。両者の一致は論理行の証明にならず、過去の出力も新規則の合格実績ではない。

## 要件・決定事項

**ユーザー合意：初回PDF補正のコード例すべてに、次の同じ基準を適用する。77・79・80は検証例であって、ページ・書名・文字列を条件にしない。**

| 原本の同じ箇所で確かめられること | 英語出力と判定 |
| --- | --- |
| 同じページ・同じコード例の所有が確定し、補正案の各非空行の全文（行内空白・数値・記号を含む）、順序・回数、行頭・相対字下げが原本の同じ出現と一意に合う | 確かめた紙面行・字下げを英語のcodeに残す。Doclingが1行に畳んでいても、それだけで棄却しない。これは**紙面表示の一致**。折返しか論理改行かの分類・実行可能性は合格条件にしない。論理的意味が分からないことだけを理由に、原文に戻す、追加空行QAを出す、または再計画する必要はない。 |
| 紙面上も1行なのに案で分割、別出現、文字・行内空白の改変、字下げ・行との対応を一意に示せない等 | 該当範囲の読めたDocling原文と既存の区切りをcodeのまま英語出力に残す。既存の位置付きQAに対象ID、ページ、ref/span・境界位置、抽出と案の差、採用内容と理由を残す。曖昧な箇所を継ぎはぎせず、所有不明部分の結合・移動はしない。QAだけに原文を退避して済ませない。 |
| 紙面の非空行は確認でき、**追加空行数だけ**不明 | 両方の非空行・字下げとDoclingの既存改行・空行を維持し、案の余分な空行は足さない。前後両行の位置・差・採用内容・不明理由をQAに残す。他の差がなければ受入可。固定との完全一致や空行数の復元成功には数えない。縦の間隔だけで空行数を決めない。 |

確認は補正案と原本の局所照合に限定する。抽出で既知の文字・既存改行・リテラル内の空白などを勝手に改変しない。案の文字を空白除去した結果、refの切れ目、行頭座標、抽出器の生成改行、AIの主張のいずれか一つだけでは採用しない。紙面の対応は確認できても論理的意味が不明な場合と、紙面の対応そのものが不明な場合を取り違えない。

**通常本文の語間は第4改訂どおり。** 所有が確定し案側の半角SPACE 1個だけが差のとき、同一spanの同一出現・同一行・前後文脈に対応させる。明示SPACE、または左右別描画の実文字の通常字送り（フォント・サイズ・方向・変換を考慮）に対し境界だけに周囲の揺れや誤差では説明できない追加余白があれば採用し、この差のQAなし。PDFiumの生成SPACE・描画分割・小さい残差だけ、単語内の字間調整、別出現・折返しは不可。不明ならDoclingを実翻訳入力に保持し位置付きQA。不正hash・破損・未知方式は読みの不確かさでなく検証エラー。

## 制約・対象外

- 未コミット・未追跡変更（未知方式orphan拒否を含む）、原本、固定期待・指紋・今回の証拠、旧Workspace・attemptを保持する。commit／stash／破棄、旧成功の書換え・修復・再翻訳は行わない。
- trial 15停止marker（累計15 trial／140予約）にアクセスしない。実AI送信・追加retry・OCR追加・モデル取得・認証変更・無断install／共有環境変更なし。書籍本文・画像・生回答・秘密をstdout／Git／Issueに出さない。固定正解は比較側だけで読む。
- ページ・書名・文字列・hashの例外、コマンド辞書・新しい構文解析器／語分割器、原本の全面再抽出・永続索引・新しいQA管理機構は不要。一般のコード整形・表再構築・新規跨ページ接続・EPUB・全冊判定は対象外。#98〜#101は変更しない。#101には固定との差と未確定事項を示し、統合側の期待と衝突すればそこで確認する。原本の反復read／hash性能は延期する。

## 実装方針

1. `src/doc_translate/pdf_adoption.py` と `pdf_correction.py` の検証済み回答→採用chunkの境界で判断する。同じ例の連続refは扱うが、候補探索の緩い一致を採用・所有拡張の根拠にしない。draft hashで検証したjob固有の原本bytes、所有ページ、span・前後文脈、座標原点・実寸を使う。既存の紙面照合で足りる箇所は再実装しない。core依存 `pypdfium2==5.14.0` とlockを維持し、PDFium open・読取・closeのみプロセス内で直列化する。
2. 第4改訂の6指摘は引き続き完了条件とする。(1) 同一itemのprovenance span間の既知の区切りを保持。(2) 混在根拠でも数値token全体を照合し、100→180／1000・小数への改変では他の正しい内容を残し、保護解除後の実unitには元の数値と位置QA。(3) calloutは最終英語codeの意図した表示行に対応させ、範囲内でも別行に付けない。(4) 画像だけの所有主張で別出現・別役割の本文を消費せず、図内外・入れ子・表／セル・除外を越えない。(5) 折返しの指摘は上記共通基準で検証し、物理配置を論理行の証明にしない。(6) 独立した脚注・captionを例に取り込まない。
3. 新しい採否は別の方式値と対応chunk版にし、方式なし／1、`owned-text-v1`／2、`owned-ranges-v2`／3、生成済みだが未受入の `owned-layout-v3`／4は従前の規則・byteで再読／再利用する。旧版に新しい意味を割り当てない。新規採用・成功再利用・該当orphan回収・別process loadで同じ結果を得る。`_matches_request → _saved_correction → _make_chunk` で該当draft・scope・要求・configの検証済み成功orphanが未知方式ならpreflight／送信／追加attempt前に拒否する。別要求を巻き込まない。方式取り違え・入力／画像／chunk改変・再構成不一致を拒否。`pdf_source`・`revise`・run/resumeのconsumerを維持する。
4. `docs/reference/artifacts.md` に採否・互換と固定差の意味、`docs/reference/usage.md` に英語codeが示すものと位置付き要確認、`CONTRIBUTING.md` に関係する検査・依存／licenseを反映する。実操作の更新先は既存 `.pi/skills/verify-project/`。正式な過去のPlanや固定正解を新方針に合わせて編集しない。

## 完了条件

- 75枚目境界を含む76–80の欠落50項目が、隣接所有chunkとの合計で、役割・位置・順序・回数を保って実units／英語出力に届く。全体失敗やQAへの退避では不可。
- 固定9対照を個別に内容・役割・構造・出典・相対順・回数まで比較。76の行末hyphenはDocling＋位置QA。78のSPACEは原本の描画で裏付け、実unitに採用しこの差のQAなし。
- コード3対照は同じ基準で、固定・原本の該当位置・採用結果・実英語fenceを照合する。77・79の複数ref、79のJSON、80の紙面5非空行（第4→第5を含む）・第2行の字下げ・数値、周辺脚注／除外を保つ。codeは翻訳unitにならず正しいところに1回。紙面の行内文字・対応・字下げの不一致を、追加空行だけの許容差で相殺しない。文字が変わったまま「紙面一致」とすることも、5行出たことを「論理5行復元」とすることも不可。
- 6指摘と未知方式の無送信拒否、旧版のbyte不変、新方式の保存再読を最終出力・QA・送信記録で確認する。再開後の実測で判定し、過去のchecks・Review・Code Review Approveは流用しない。

# #97 初回PDF補正で本文を取り戻し、根拠のあるコード改行を保持する（第2改訂）

## 目的

初回PDF補正の回答が読み取れた内容を落としたり変えたりしても、所有範囲の原文を元の位置・役割で利用者に届ける。本文は翻訳入力、コードは非翻訳の英語出力で確かめる。印刷されたコード例を保持することが目的であり、実行用ソースへの変換ではない。

正式入力は [#97 の前回再開コメント](https://github.com/minorunakamura/doc-translate/issues/97#issuecomment-6985206964) と [直前の Approved Plan](pdf-initial-source-preservation-97.md)（SHA-256: `6aa8771aa29451296ae09484fe6d17497632fa087e7265e6d8cbd2bc4d69553b`）。#97 では本改訂を優先する。前回 Plan、[共通 Plan](pdf-initial-source-preservation.md)、固定資料は履歴としてそのまま残す。#98〜#101 の範囲・依存・承認は変更しない。#101 には局所差・未解決を区別して引き継ぎ、統合受入れと旧期待が衝突すればその作業で再確認する。

## 要件・決定事項

**今回変更する契約は一つ。** 従来、原本の局所照合は通常本文の同位置の語区切りだけだった。これに、**所有が一意な同一ページ・同一コード例（listing）で、提示された行境界・字下げを確認する場合**を加える。次の採否と判定不能時の扱いはユーザー確認済み。

| 状況 | 採用する原文とQA |
| --- | --- |
| Docling に改行・字下げ・空行が既にあり、対象の所属が分かる | 文字とともに保持する。案による削除、改行位置の移動、引用内の空白変更を「整形」として通さない。 |
| 案にだけあるコードの行境界・字下げ | まず所有が確定した範囲を、同じ位置の原本に文字列全体と順序・回数・前後文脈で対応付ける。各行の全文・境界と、必要な字下げ・空行をそれぞれ照合し、案の配置が一意に裏付けられた部分だけを残す。同じ listing の連続した複数refも可。単一spanであることだけで改行を否定しない。 |
| 所有は確定するが、案の改行・字下げと原本が合わない、折返しと意味のある改行を区別できない、または文字層・位置対応が足りない | 当該範囲の Docling の読めた文字・既存改行を code のまま採用。対象ID、ページとref/span等の位置、抽出と案の差、拒否／未確定の理由を既存QAに残す。英語出力に原文が残ることと、改行を正しく復元できたことは別。安全に局所化できない差を継ぎはぎしない。 |
| 通常本文の脱落・文字差・語区切り | 所属・読順の分かる欠落はDoclingの読めた所有部分を元の位置に1回戻す。同位置・同一行で裏付けられた局所の語区切り以外、読める文字が相違すればDoclingを翻訳元にし位置付きQA。数値・URL・識別子・記号の訂正に広げない。 |
| 所有／所属自体が不明、または元から不読 | 読めた確定部分を守り、不明部分は推測で移さず既存の未解決・失敗経路へ。空白ページ、図内部、復元成功として処理しない。hash不整合や未知方式は単なる判読不能ではなく検証エラー。 |

照合は**既存の案の検証**であり、座標からコード・空行数・インデントを生成しない。等幅の実測字送りと共通の行頭との対応は、行の内容と順序が一致した場合の字下げの根拠にできる。単なる縦横の間隔、空白除去後のtoken列一致、別出現、AIの主張は根拠にならない。見た目の折返しだけで文や文字列を分断しない。

## 原因と再計画の根拠

- 調査時 HEAD は `591086c`、対象は未コミットの部分実装を含む。旧版は回答のページ・個別根拠を検証しても本文の網羅を保証しない。採用chunkで消えた内容は後段の組立や翻訳で取り戻せない。
- 前回Planに記載の `work/issue83-survey-xcP1KLJ7/root-final/{fixed-expectations,missing-content-gold,hashes}.json`、同親の `root-survey/seed-76/`、`work/design-and-build-great-web-apis/` の保存chunk・draft・raw・原本を比較対象とする。今回、hashを照合した同じ原本byte列を、該当provenanceの枠内で読取専用確認した。80の対照はDoclingのorig/textとも1 span・1行。原本は対照と同じ行内文字を持つ5物理行で、第2行のみ字下げ1。局所文字列にはこの先頭空白はないが、同一枠の各行頭は第2行だけ等幅1字分（約4.67 pt）右である。これは照合手段の根拠であり、意味判定の万能な指標でも改修後の成功でもない。77・79の対照は複数ref・空行を含み、1 span専用の対処では足りない。
- 現差分の `pdf_adoption._line_formatting` は原本を見ずに `return value` と `return\nvalue` を同等とする（人工入力で確認）。`_bind_neighbors` の範囲拡張と `adopt_owned_ranges` の最終採用の両方で使われる。片方だけ直しても所有または出力に誤りが残る。以前の実動結果・反例は `work/test-verification-97-root-G9YcNpDM/{book,root-review-counterexamples}.json`。過去に50項目・9対照を通したことは新規則の証明にならない。

## 実装方針

1. `src/doc_translate/pdf_correction.py` の検証済み回答→採用chunkの共通境界で判断する。`pdf_adoption.py` の既存の読順・所有span照合と局所PDF読取を使う。原本はdraftのhashを検証したそのbyte列だけを使い、所有ページ・範囲・座標原点・実寸を確かめる。コードの同一箇所の照合は行内の文字（数・記号・リテラルを含む）、行の並びと境界、相対字下げ・空行を分ける。既存の読順・独立した行やgroupの境界は根拠となり得るが、refの切れ目を無条件に改行としない。候補探索のゆるい一致を採用・所有拡張の証明に流用しない。原本の全面再抽出・永続索引・構文解析器の導入は不要。
2. **次の4件は新仕様ではなく、前回Plan内で直せる未完の指摘。** 現差分と照らし、再開後の回帰に含める。

   | 指摘と現状 | 是正・観測する結果 |
   | --- | --- |
   | 混在根拠：抽出ref＋画像等の案で、`original in item.text` なら案全体を通す。保存反例は100→1000、QAなし。 | 部分文字列で数値全体の一致としない。所有を分離できるところは他の正当な内容を保ち、読めた数値は100、差は位置付きQA。元の100→180の保証も維持。分離不能部分の創作や、確定数値まで失う全体拒否で代用しない。 |
   | 別出現の空白：`_supported_space` はbbox内の単語対が1件でも前後文脈を照合しない。枠内の別文だけにSPACEがある人工例で採用を確認。 | 対象spanの順序・周囲・同一行まで一意に対応した場所だけで判断。別文・別行・繰返し・対応不能ならDocling＋位置QA。正しい78のSPACEは落とさない。 |
   | 所有と読順：`_reading_order` はgroups以外の子を辿らず、人工の入れ子2項目を1件しか訪ねない。本文rangesだけの隣接判定には途中の画像・表が見えない。 | rawの実際の親子・所有span・図内外・caption・脚注・table/cell・除外を区別する。本文以外や画像のみのblockも含む順序で、根拠のない飛越し・結合を防ぐ。独立図や表を末尾に移さず、内側を独立本文に二重採用せず、外側本文を隠さない。曖昧なら所属を拡張しない。 |
   | 未知方式のorphan：`_matches_request` のfalseが `_saved_correction` → 未回収となり、単体correct・run/resumeの探索から新規生成へ進み得る。既存のchunk load拒否テストだけでは送信を止めたことにならない。 | 今処理する範囲・要求・configに該当する保存成功で、方式だけ未知なら未処理とみなさず、生成・preflightの前に明示拒否。送信・追加attempt・旧記録変更ゼロ。別draft・別scope・正当に異なる要求まで一律に処理を止めない。 |

3. 保存形式は**新しい採否には新しい方式値と対応するchunk版**を使う。方式なし／schema 1、`owned-text-v1`／2、部分実装が既に出力した `owned-ranges-v2`／3を新解釈で再生しない。旧方式は当時の入力・回答・規則とbyteで厳密に再読／再利用し、新方式だけに今回の採否を適用する。新規採用・成功再利用・該当orphan回収・別processのloadで同じ記録から同じ結果。方式取り違え、入力・画像・chunk改変、再構成不一致を拒否する。方式追加だけで旧成功を再送・移行しない。`pdf_source`、`revise`、run/resumeのconsumerも維持する。
4. 前回承認のcore依存 `pypdfium2==5.14.0` とlockを維持する。job固有の原本を使い、PDFiumのopen・読取・closeのみプロセス内で直列化する。補正処理全体を直列化しない。EPUBや従来から原本照合しない方式に新しいnative処理を持ち込まない。
5. 文書は `docs/reference/artifacts.md` に各方式の再読・採否・根拠、`docs/reference/usage.md` に処理済みと位置付き要確認の区別、`CONTRIBUTING.md` に関係する検査・依存／licenseの案内を反映する。直接操作は既存の検証Skillの該当節に置く。

## 制約・対象外

既存dirty差分・未追跡・部分実装を出発点として保持し、無断commit／stash／破棄をしない。原本・旧Workspace・attempt・固定期待・対照指紋・trial 15 の停止markerと累計15 trial／140予約をそのまま保つ。実AI送信・追加retry・旧版の修復／再翻訳・新OCR・モデル取得・認証変更・無断install／共有環境変更なし。書名・ページ・ref・特定文字列・検証正解やhashを製品の採否やモデル入力に使わない。コードの一般整形・表の再構築（#98）、新しい跨ページ接続（#99・#100）、全冊評価（#101）、EPUBの動作変更は対象外。

## 完了条件

- 75境界を含む76–80の欠落50項目が、隣接する所有chunkとの合計で、所有部分・順序・回数・所属を守って残る。翻訳対象は実際のunits、非翻訳部分は英語出力に届く。QA・退避だけ、全ページ失敗、片方の全文への丸投げでは不可。
- 既存9件を1件ずつ固定対照と対応付ける。内容・役割・構造・出典・相対順・回数を保ち、局所差以外は一致する。78の裏付けのあるSPACEは採用、76の行末hyphenは語中に必要とは確認できないのでDocling＋位置QA。コード3件は空行・行内空白・字下げを含む全文を確認する。80は5行・第2行の字下げ、79のJSONや80の数値、周辺の脚注・除外を保つ。固定対照に合わなければ差と根拠を残し、未達のまま扱う。曖昧時の安全なfallbackは対照不一致を合格に変えない。
- 同じコード・同じ案でも、別の自作PDFの同一箇所で裏付けが変われば採否が変わる。根拠なしに意味を変える改行を通さない。上表4件が、最終出力・QAまたは無送信拒否まで成立し、新旧方式の保存・回収・再読が混ざらない。

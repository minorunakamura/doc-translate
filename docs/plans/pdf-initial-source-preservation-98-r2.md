# #98 第2版：PDFの紙面どおりにコードの行と字下げを残す

## 目的

[Issue #98](https://github.com/minorunakamura/doc-translate/issues/98) の英語出力で、ファイル名とコードを分け、紙面から確認できる行を落とさない。PDFの枚数は先頭を1とする。今回変えるのは **116枚目（紙面102ページ）の共通の左余白に関する出力・QA・採点**。追加空行や他のページの許容差は広げない。

本版は [旧#98 Plan](pdf-initial-source-preservation-98.md)（SHA-256: `e30ca5921f19c0d14fa10ff04dd9c828b3934371d97e65d8f0333d60e32ee95a`）と[従来のWork Item指示](https://github.com/minorunakamura/doc-translate/issues/98#issuecomment-7004768663)に対し、以下の判定を優先する。旧Plan・元の[全体Plan](pdf-initial-source-preservation.md)・[#97 第5改訂](pdf-initial-source-preservation-97-r5.md)・固定資料は変更しない。

## 要件・決定事項

| 対象 | 英語出力と合格条件 |
| --- | --- |
| 115枚目（紙面101ページ） | ファイル名をcaptionとして元の位置に1回だけ残し、コードに混ぜない。4非空行の文字・字下げ・順序・回数を原画像と照合する。 |
| 116枚目（紙面102ページ） | 29非空行をコードとして出す。最も左の印刷行を**表示上の0桁**とし、他の行はそこから紙面で測れる字数だけ下げる。最初の行は下の本文の行頭と同じ位置にある。各行の本文（内部空白・記号・数値を含む）、順序、回数、相対字下げはすべて合うこと。元ファイルの絶対字下げは断定しない。コードを翻訳unitにせず、抽出の1行に戻したり、QAにだけ29行を残したりしない。 |
| 共通の左余白のQA・採点 | 既存の位置付きQAから当該断片・対象行・出典を特定でき、確認できた行頭差、提案と採用表示の違い、共通の先頭字数は原本から裏付けられない理由が分かること。各行の出典へ辿れれば同じ警告を29件作る必要はない。**出力後**に未変更の固定期待と各行を比較し、「紙面の文字と相対字下げは一致」「出力は見本より全29行で2字浅い」「著者の絶対字下げは未確認」を区別する。紙面どおりで、この共通差以外に字下げ・文字等の誤りがなければ、この項目は合格。固定文字列との完全一致・元コードの完全復元とは数えない。個別行のずれ、断片の任意の左右移動、非空行の脱落・入替えは不合格。 |
| 追加空行（**独立判定**） | 旧#98 Planどおり。抽出済みの改行・空行は残し、案にだけある追加空行は足さない。各不明境界で前後両行の出典・位置、案／採用の差、不明理由を既存QAに残す。これを満たせば追加数不明は許容するが、固定期待の8空行の復元・41行完全一致とは報告しない。左余白のQAでこの両側QAを代用しない。 |
| 346枚目、119–121枚目 | 346の6行×2列は全12セルを個別に原画像・出典・実units・英語表に対応付け、位置・内容・URL・数値、欠落／入替え／重複なしを確認する。119–121の既知の21行（従来各2字不足）は最終断片・英語出力で行別の残差と位置QAを別記する。116の許容を転用せず、修復済み・跨ページ接続成功とはしない。 |

### 判断の根拠

- 停止時のブランチは `fix/pdf-source-preservation`、HEADは `34e86f2`。部分実装による4 chunk再生からfresh load・英語出力までの記録 `work/issue98-implement-AYATFmre/stop.json` では、115／116は4／**1**非空行。これ以前の所有競合と経緯は旧#98 Plan「停止理由と証拠」。採用処理 `pdf_adoption.py::_listing_layout` は原本行と案の行頭がそのまま一致する行を要求し、判定できないと抽出文字列に戻す。確認済みの29行まで一括して失うことが問題。
- `work/issue98-root-anchor-SnxwM7jR/{decision,baseline-comparison}.json` と原本を照合。116の最初のコード行と直後の本文段落の先頭はどちらも x=90 pt。29行の文字・行頭差と字送り（4.672 pt）が確認できる。見本の字下げを当てると仮想の0桁は80.656 ptになるが、その位置が元コードの起点だという証拠はない。**紙面上の左端は分かる。元コードの共通の空白数は分からない**。本文段落との整列はこの標本の独立照合であり、全PDFで本文を探す製品要件ではない。
- 固定比較元は `work/issue83-survey-xcP1KLJ7/root-final/{fixed-expectations,code-gold,hashes}.json`、同親 `root-survey/seed-{111,346}/` の原画像・対応表。115–116の見本は以前の変換結果をつないで原画像と比較したもの（同親 `worker/prepare-expectations.py`、`root-fix-expectations.py`）。著者の元ファイルではない。停止時の測定・部分実装・過去のReviewは、新しい出力の合格証拠ではない。

## 制約・対象外

- 既存の未コミット・追跡外変更、原本・raw・旧attempt／chunk・固定資料・調査証拠を保持する。独断のcommit／stash／破棄、旧Workspaceの修復・移行・再翻訳をしない。実AI送信、追加retry、認証、外部trial markerへのアクセス、OCR・モデル取得、無断install・共有環境変更なし。書籍本文・画像・生回答はprivate限定。
- 固定期待、特定のページ番号・文字列・座標・2字という既知値を製品の採否やモデルに渡さない。全行の先頭空白を個別に落とした比較だけで合格にしない。論理ソースの復元、全面再抽出、新しい永続索引・QA管理・CLI、一般のlist再構築、EPUB、全冊評価は対象外。#99・#100の接続、#101の統合受入れ条件は変更しない。#101には実際の差と未確認事項を渡す。

## 実装方針

1. 現差分を保持して `pdf_correction.py::_make_chunk` → `pdf_adoption.py::adopt_owned_ranges` と局所の印刷行判定を確認する。caption・コード・周辺本文は同じ所有ページ／出現／有効spanの読順と非重複を守る。元の文字を一度だけ正しい役割で残す。近くに似た行がある、所有が重なる等の曖昧さを先勝ちで解決しない。
2. 局所の所有・行対応・順序・行内文字と、必要な等幅字送り／行頭差が裏付けられ、未確定なのが断片全体に共通のずれだけなら、**断片全体に一つの表示基準**を使う。裏付けのある既存の字下げ・区切りを壊さず、原本が支持しない提案上の共通余白は足さない。起点が確かな経路と、文字・行・相対位置まで不確かな拒否／抽出保持経路を区別する。単に既存の最終チェックを外して提案の空白を通さない。追加空行の判定・両側QAは再利用し、位置・差・理由は既存uncertaintyから英語出力のQAまで追えるようにする。表のセル所属は個別確認し、不一致があれば元の所有根拠に戻る。
3. 方式なしから公開済み `printed-lines-v4`（chunk版5）までの再読／該当orphan／成功再利用は旧規則・旧byteを維持する。部分実装には `printed-ranges-v5`（版6）とその隔離証拠がある。既存の保存物に新しい意味を遡及させず、変更する規則は既存の方式識別と版分岐で区別する。新規採用とfresh loadが一致し、未知方式・改変・再構成不一致を拒否し、方式追加だけで旧成功を再送しない。
4. 公開の採用・再読契約は `docs/reference/artifacts.md`、英語出力とQAの読み方は `docs/reference/usage.md`、再生・採点手順は `.pi/skills/verify-project/` の関係節に反映。開発チェックの入口が変わる場合のみ `CONTRIBUTING.md` のPDF補正節を更新。

## 動作確認方法

- **TDDは変更する採用規則だけ。** 既存の `tdd` Skillと `tests/test_pdf_correction.py` の小さな自作PDFを用い、公開 `correct_pdf → load_pdf_correction → assemble_pdf_source` と英語出力・QAで、共通余白だけ証明できない例が行を失う失敗から確認する。期待は表示上の0桁、行頭差・可読文字の保持、該当位置のQA。相対差そのものが違う提案を通さないこと、既に確かな字下げ、既存のcaption／所有・文字差（Doclingの値と位置QA）・抽出済み空行／追加空行の対照を使う。表の規則を変更する場合だけ軽い入替え回帰を追加。保存再読・実資料の比較・CLI・文書は非TDD。新しい常設E2EやCIは不要。
- **書籍は無送信の閉じた再生。** `.pi/skills/verify-project/SKILL.md` と同配下 `references/feature-map.md` の「所有本文の採用・保存再読（#97）」「PDF原文標本準備」「保存記録と詳細検査」を使う。原本・draft・旧回答は `work/design-and-build-great-web-apis/`。所有111–115、116–120、121–125、346の4 chunkだけを各requestの参照範囲のまま使い、画像hash・projection・所有・順序・回答全体を照合する。旧attempt／chunkを新規成功としてコピーしない。新しい0700親で採用→fresh load→units・英語・QA。部分実装の `scripts/pdf_adoption_replay.py --listings`／`scripts/pdf_listing_comparison.py`（Skill相対）は4件の観測を取る入口であり、それだけでは採点ではない。
- **Rootによる独立照合。** 原画像・局所文字位置・行頭と字送りを英語fenceの該当各行に対応させる。115の4行・caption、116の29行は内部空白を含む文字、原順／回数、紙面から測った表示列を個別に検査。0桁の行も照合する。出力と見本の先頭字数の差を全行で確認し、一律の2字差以外を見逃さない。共通余白のQAと追加空行の各境界の両側QAを別々に追う。346の12セルと119–121の21行は別の検査結果として残す。採用関数自身を採点器にせず、過去のMap成功を今回の検証結果にしない。

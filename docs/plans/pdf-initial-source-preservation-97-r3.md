# #97 初回PDF補正で原文を保持し、裏付けのない空行数は未確定として扱う（第3改訂）

## 目的

初回PDF補正の案に脱落・文字差・改行差があっても、読み取れた所有範囲の原文を正しい位置と役割で利用者に届ける。本文は実際の翻訳入力、非翻訳のコード例は英語出力で確認する。印刷されたコード例を保持するのであって、実行用ソースを復元する仕事ではない。

正式入力：[Issue #97 の第2改訂コメント](https://github.com/minorunakamura/doc-translate/issues/97#issuecomment-6987655325)、[第2改訂 Plan](pdf-initial-source-preservation-97-r2.md)（SHA-256: `83459e25a2536c402ae47bb8fe5ffb9318fba632bad7ee37f9c50e206e8c9dbc`）。**#97 で変更するのは、空行数だけを一意に裏付けられない場合の受入条件。** この点では第3改訂を優先する。他の保証・対象外・検証は第2改訂を維持し、過去の Plan・固定資料を修正しない。

## 停止理由と判断の根拠

第2改訂は「根拠のない空行を採らない」と「固定対照の空行まで一致しなければ未達」をともに求めていた。保存された案と `work/test-verification-97-r2-root-0AOd9nly/{r2-blank-line-evidence,r2-empty-show-positions}.json` を照合した結果、77ページの3境界と79ページの1境界は、非空行の全文・順序は一致するが、通常約10.86 ptに対して約16.30 ptの間隔で、当該位置に空行数を示す文字情報は確認できない。79ページの別の約21.73 ptの境界も、それだけで空行数の証明にはならない。これらは観測であって製品の閾値・例外表ではない。

ユーザーと合意した判断は、**段落分離を一律に空行1つと表現せず、出力で守れた原文と、決められなかった空行数を別々に示す**こと。同じ条件の境界が次に見つかっても、ページごとに再計画しない。

## 要件・決定事項

| 同じ位置で確認できたこと | 採用と受入れ |
| --- | --- |
| Docling に既存の改行・空行・字下げがあり、所属が明確 | 読めた文字とともに保持する。固定対照や案に合わせて削除・移動しない。 |
| 同一ページ・同一コード例の所有範囲が一意で、案にだけある配置を原本が裏付ける | 連続する複数refも対象。非空行の全文・順序・回数・前後文脈、行境界、行内空白、相対字下げ、空行数を分けて照合する。裏付けた配置だけを残す。原本の同位置の等幅字送りと行頭は字下げの検証に使える。 |
| **非空行の境界は確認できるが、その間の追加空行数だけは確認できない** | 両行を連結せず、確認できた行・字下げと Docling の既存改行は英語出力に残す。案の余分な空行は足さず、「原本にも空行がなかった」とは断定しない。既存QAで、対象ID・ページ・ref/span等と前後の行の位置、抽出と案の差、採用内容と未確定の理由が分かるようにする。**この出力と位置付きQAの両方を確認し、他の差がなければ #97 として受入可。** 固定対照との差は比較結果に明記し、完全一致・復元成功とは別に数える。 |
| 非空行の境界・字下げ自体に根拠がない、折返しと区別できない、または差を安全に局所化できない | 第2改訂どおり、当該範囲の読めた Docling 原文・既存改行を code のまま採用し、位置付きQA。空行の受入条件を、非空行や字下げの不一致、コード例全体の比較免除に広げない。所有自体が不明な部分を推測で結合・移動しない。 |
| 通常本文の欠落・文字差 | 所属・読順が確定する欠落を元の位置に1回戻す。同位置・同一行で一意に裏付けた局所の語区切り以外、相違は Docling を翻訳元に採って位置付きQA。元から不読・所属不明は既存の未解決／失敗経路へ。 |

単なる縦横の間隔やrefの切れ目、空白を取り除いたtoken列の一致、別出現、AIの主張は配置の証明にしない。座標からコードや空行数を生成しない。不正hash・未知方式は「空行未確定」ではなく検証エラー。

## 制約・対象外

対象は `minorunakamura/doc-translate` の #97。既存の未コミット差分・未追跡ファイル・未知方式orphan拒否の部分実装を保持して引き継ぐ。無断commit／stash／破棄なし。旧Workspace・attempt・原本・固定期待・対照指紋・trial 15停止marker（累計15 trial／140予約）を変更しない。実AI送信・追加retry・旧版の修復／再翻訳・新OCR・モデル取得・認証変更・無断install／共有環境変更なし。書名・ページ・ref・文字列・検証正解・hashによる製品の分岐やモデルへの正解入力は不可。一般的なコード整形、EPUB変更、表再構築・新しい跨ページ接続・全冊評価は対象外。#98〜#101 の範囲・依存・承認はそのまま。#101 へは固定対照との差・未確定を明示し、統合受入れが旧期待と衝突したらそこで再確認する。

## 実装方針

1. `src/doc_translate/pdf_correction.py` の検証済み回答→採用chunkで規則を統一する。`pdf_adoption.py` の候補探索と所有拡張・最終採用を区別する。現状の `_line_formatting` は原本なしに空白→複数改行を許し、`_bind_neighbors` と最終採用で使われる。ゆるい候補一致をどちらの証明にもせず、draftのhashで検証した同じ原本byte列を所有ページ・provenance枠・座標原点・実寸に対応付ける。原本全面の再抽出、永続索引、構文解析器、新たなQA管理機構は作らない。
2. 第2改訂の4件を維持する。①混在根拠でも部分文字列一致で数値を通さず、100→180／1000なら翻訳入力は100＋位置QA。他の正当な内容を消さない。②同じ枠の別出現・別行にだけあるSPACEを採らない。③rawの入れ子・図内外・caption・脚注・表／セル・除外と途中の非本文blockを考慮し、所属・順序・回数を保つ。④今回のdraft・scope・要求・configに該当する検証済み成功orphanが未知方式ならpreflight／生成前に拒否。追加attempt・送信・旧記録変更ゼロ。別要求は巻き込まない。④は `_matches_request` → `_saved_correction` → `_make_chunk` と単体回帰に部分実装あり。捨てて作り直さず、単体correctとrun/resumeからの回収を区別して現差分を検証する。
3. 新しい採否に新しい方式値と対応するchunk版を使う。方式なし／schema 1、`owned-text-v1`／2、保存済み `owned-ranges-v2`／3は当時の規則・byteで再読／再利用する。新規採用・成功再利用・該当orphan回収・別processのloadで同じ記録に同じ結果。方式取り違え・入力／画像／chunk改変・再構成不一致を拒否する。旧成功を再送・移行しない。`pdf_source`・`revise`・run/resumeを維持する。core依存 `pypdfium2==5.14.0` とlockを維持し、job固有の原本を用いてPDFium open・読取・closeのみプロセス内で直列化する。EPUB・原本照合しない旧方式には適用しない。
4. `docs/reference/artifacts.md` に方式・再読・採否と未確定差、`docs/reference/usage.md` に処理済みと位置付き要確認の違い、`CONTRIBUTING.md` に関係する検査・依存／licenseを反映する。直接操作は既存の検証Skillに置く。第2改訂以前の Plan・固定資料・他Issueは更新しない。

- 9対照すべての内容・役割・構造・出典・相対順・回数を個別照合する。76の行末hyphenはDocling＋位置QA、78の裏付けたSPACEは採用。コード3件は行内空白・空行・字下げを含む全文を比較し、77・79の各境界も個別判定。空行差について受入可能なのは上表の条件に限る。80の5行・第2行の字下げ、79のJSONや80の数値、周辺の脚注・除外を維持する。局所差以外の不一致は隠さない。

## 要件・決定事項
1. **二重所有の拒否は維持する。** 同じ文字範囲を複数の役割に割り当てない。各分類の追加規則は、該当する抽出項目の全文字について、出典・内容・役割・紙面順・回数を**一通り**に説明できる場合だけ、重ならない範囲を各ブロックに割り当てる。単にbboxが重なる、近い、先頭が一致する、同じ文字列がどこかにある、正規化すれば似る、という理由では分けない。説明できなければ従来どおりchunk全体を拒否する。QAだけへの退避・先勝ち・候補削除・出典の黙った削除で保存しない（第2版要件3を維持）。
2. **分類別の限定証明。** 実装は既存の `_printed_role_split`・`_listing_layout`・`_caption_listing_parts`・`_body_punctuation`・`_mixed_phrase_matches` 等を優先して拡張し、次の条件で成立させる。
   - **A：** 題名がそのコードを指すこと（`target_id`、またはtargetがなくても同一項目内で直後のコードしか該当しないこと）、共有項目が先頭・末尾のどちらにあっても扱うこと、全行の描画照合が成り立つことを証明できる場合だけ分ける。提案の文字訂正（誤字修正等）は採用しない。抽出文字を保持し、差を位置付きQAに残す。
   - **B：** 本文ブロックは抽出中の一意な位置で確定する。コードブロックは、残りの範囲を紙面上の行に一意に対応付けられる場合だけ割り当てる。正規化して一致する提案の改行・字下げ・引用符は、証明できなければ抽出文字＋根拠のある改行とし、差を位置付きQAに残す。同一文字列が複数ある場合は、紙面順と他ブロックの範囲で一つに決まるときだけ割り当てる。前後の項目にまたがるコードは、各項目内の範囲がそれぞれ一意に決まる場合だけとする。
   - **C：** 本文同士の共有も、各本文の範囲が抽出順に隙間・重なりなく一意に決まる場合だけ割り当てる。一致判定で許すのは、既存の検証済み記号規則で同一と証明できる差（引用符の字形等）だけとする。採用文字は抽出側に従い、差はQAに残す。
   - **D：** 出典に抜けた中間項目は、他のブロックが所有せず、同じページの紙面順で前後の出典の間にあり、その全文がブロック本文の対応位置に一度だけ現れる場合に限り、そのブロックの範囲として扱う。それ以外は従来どおり拒否する。リストの marker と本文の分割、索引等の分かれた断片は、断片ごとに一意な位置で照合する。連結した文字列での照合は行わない。表の出典（`#/tables/*`）の扱いは変えない。
3. **保存後の契約。** 題名・本文は実際の翻訳unitに各1回、コードの可読行は元順で各1回、英語のコード欄に残す。ページ・各出典範囲・対象関係・前後の本文順が保存後も辿れること。81/83/190の既存の不読や局所QAを補わない。
4. **全70件の成功が必須。** 統合は、全70 chunk を除外なしに新方式で新規保存できた場合だけ進める。1件でも拒否が残れば統合未達とし、再生を繰り返したり期待を緩めたりせず、BLOCKED または REPLAN_REQUIRED として停止する。
5. **既存成功分の不変確認。** 第2版で保存できた56件の新方式での採用結果（blocks・出典・QA）を第2版の採用結果と比べ、差をすべて列挙して原画像で判定する。81–85は第2版の局所完了条件で判定する。

## 実装方針
- 共通の採用経路 `pdf_correction._make_chunk → pdf_adoption.adopt_owned_ranges` だけを変更する。最後の二重所有検査（`Overlapping ownership of extraction text`）と非隣接・切り出し不能の拒否は、規則が成立しない場合の結果として残す。分類ごとの小さな関数で、範囲・読順・QAを返すか、Noneを返す。
- 新規の採用規則はすべて `layout_version >= 15`（新方式）の条件下に置く。v13以前の方式は当時の規則で再構成・byte一致を確認し、旧方式の出力を新方式へ昇格・書換えしない。方式が未知・改変・取り違えのchunkは拒否する（第2版どおり）。
- 文書は第2版どおり `docs/reference/artifacts.md`、`docs/reference/usage.md`、`.pi/skills/verify-project/`（SKILL・Feature Map）に不足分だけ追記する。今回の新規採否（A〜D）と全70件の再生手順を加える。

# #109 原本に描かれた囲み（sidebar）を独立した単位として扱い、ページ間の本文接続（91→92、61→62）を回復する

## 目的
[#109](https://github.com/minorunakamura/doc-translate/issues/109) の2組を直す。どちらも、ページをまたぐ段落の前半と後半の間に、囲み（sidebar）が入っている。そのため、assemble の Contradictory continuation（間に入ってよいのは脚注だけ）により接続されず、両断片が残る。
新しく PDF を処理する利用者の出力で、2組の段落を1回だけ接続する。囲みは独立した単位として1回だけ残す。紙面での位置も回復する（91枚目は見出しより上）。

**前提：** 元の全体 Plan [pdf-initial-source-preservation.md](pdf-initial-source-preservation.md) の要件・制約（Docling の文字を基準にする、正解・ページ番号・特定 ref を判定に使わない、旧記録は旧規則で厳密に再読する、など）を引き継ぐ。#101 の各版（[第5版](pdf-initial-source-preservation-101-r5.md)・[第6版](pdf-initial-source-preservation-101-r6.md)）と、旧 Plan・固定見本は書き換えない。#101 は完了済み（`1459aaa`）。

**入力設計からの変更（ユーザー確認済み）：** #101 第4版は「座標による位置決め」を新しい種類の規則として禁止した。この禁止は #101 に限った制約である。#109 では、下の要件1の「原本の描画枠による囲みの判定」と、要件2の「囲みの位置決め」に限って使ってよい。それ以外の座標規則（距離・幅・特定ページによる結合など）は、引き続き追加しない。

## 要件・決定事項
1. **囲みの判定（採用時、新方式だけ）。** 次をすべて満たす場合だけ、ブロックの集まりを1つの囲みと判定する。
   - 原本 PDF の同じ所有ページで、つながった描画（塗りの矩形と横の罫線）が1つの枠を作る。罫線だけで上下を挟む形（91枚目）と、複数の塗りが接する形（62枚目）の両方を含む。
   - 枠の中にある抽出項目は、すべて枠の内側に完全に収まる。枠の境界をまたぐ項目や、一部だけ重なる項目があれば、囲みとは判定しない。
   - 枠の中の項目は、見出し・本文・リストだけである（コード・表・図・caption・脚注を含む枠は対象外。コードの背景の塗りを囲みと誤認しないため）。図形のアイコン（91枚目の `#/pictures/24` など）が枠の中にあることは妨げない。
   - 枠の中のブロックが、すべてこの chunk の採用ブロックとして存在し、枠の外の項目を含まない。
   - 判定は原本の描画だけで行い、AI の回答に囲みの主張を求めない。回答の内容で判定を変えない。ページ番号・ref・書籍固有の文字列・固定座標は使わない。
   成立しない場合は、囲みとして扱わない（現行どおり）。chunk 全体を拒否する新しい理由にはしない。
2. **囲みの位置（採用時）。** 囲みと判定したブロックは、内部の順序を保ったまま1つの単位として並べる。同じページで、囲みの枠より上に描かれた枠外のブロックより後、下に描かれた枠外のブロックより前に置く。この位置が一意に決まらない場合（段組みなど、上下で決まらない配置）は、並びを変えない。91枚目では、囲みが見出し 1028 の前に来る。
3. **記録（新しい採用方式）。** 採用時に判定した囲みの所属を、採用 chunk のブロックに任意の囲み識別として記録する。新しい採用方式名（例：`drawn-enclosure-v15`）と chunk schema 16 を追加する。AI の回答（`CorrectionAnswer`）にはこのフィールドを許さない。保存要求・再利用・orphan 回収・`load_pdf_correction` は、既存の方式管理（`_RULE_VERSIONS`）で同じ方式に結び付ける。schema 15 以前の記録は旧規則で厳密に再読し、新しいフィールドを持つ旧記録は拒否する。
4. **接続（assemble、新方式の chunk だけ）。** 既存の Contradictory continuation の条件（相互 target、mode、構造、ページ順、間に入ってよいのは脚注だけ）に、次の例外を1つだけ加える。
   - 前半と後半の間にあるブロックが、脚注と、**1つ以上の完結した囲み**（囲みのブロックすべてが間にあり、前半・後半のどちらも囲みに属さない）だけである。
   この場合は接続し、間の囲みは接続した段落の直後（間にあった脚注の後）に、内部の順序を保って独立して置く。#100 の「図は次の非対象本文より前、非対象ブロック同士の相対順はすべて保持」と同じ扱いである。
   相手が一意でない、片側だけ target がある、間に囲みでない本文・見出しがある、囲みの一部だけが間にある場合は、従来どおり接続せず、両断片と位置付き QA・失敗した `pdf_connection` check を残す。
5. **表示は変えない。** units と render は、囲みの見出し・本文を現行どおり見出し・本文として出力する。囲みの枠を描く表示や、新しい QA 種別は追加しない。
6. **保証の範囲。** 保証するのは 91→92 と 61→62 の2組である。ほかのページへの一般化は保証しない。ただし、全70件の再生で生じる変化は、すべて原画像と照合して説明できなければならない。

## 制約・対象外
- 過去の Workspace・訳文の修復、旧 chunk の書き換え・昇格・再送はしない。実 AI 送信、retry、実認証、外部 trial marker へのアクセス（読み取りを含む）、OCR、install、共有環境の変更はしない。
- #110（212→213、コード）、#111（73→74）、75→76 など、囲みと関係のない Contradictory continuation は対象外。囲みの例外を、図・表・コードの介在や、同じ ref の分割に広げない。
- 囲みの見出しを本文の見出し階層に組み込む、囲みを訳文で枠として描く、EPUB の囲みを扱う、は対象外。
- 書籍の本文・画像・生回答・エラーは private（`work/`）だけに置き、Issue・通常 stdout・Git に出さない。
- 既存の正例・拒否例のテストの期待値は変えない。

## 実装方針
- **採用（`src/doc_translate/pdf_adoption.py`）：** `adopt_owned_ranges` に、新方式（新しい `layout_version`）だけで動く小さな関数を加える。所有ページの原本の描画（pypdfium2 の path object。既存の `_local_text` 等と同じ原本読み取り経路）から枠を作り、要件1で囲みを判定する。要件2の位置を、既存の `ranks` を更新して反映する。枠の作り方（どの path をつなぐか、許容誤差）は、自作 PDF の正例・拒否例と、書籍の2ページで成立する最小のものにする。
- **方式と記録（`src/doc_translate/pdf_correction.py`）：** `ADOPTION_RULE` を新方式名に、`_RULE_VERSIONS` に旧 `drawn-caption-listing-v14: 15` を残して新方式を 16 にする。`PDFCorrectionChunk.schema_version` に 16 を加える。囲み識別は採用ブロックだけの任意フィールドとし、AI の回答では拒否する。schema 15 以前は旧規則で再読する。
- **接続（`src/doc_translate/pdf_source.py`）：** `assemble_pdf_source` の接続判定で、要件4の例外を加える。囲み識別は schema 16 の chunk から読む。並びの移動は、既存の結合処理（`edges` と `order`）の中で、間の囲みを結合した段落の直後に置く形で行う。
- **文書：** `docs/reference/artifacts.md` の schema 15 の節に続けて、新方式（schema 16）の囲みの判定・記録・接続と、旧記録との関係を書く。「既知の未解決」の #109 の項目を、解決済みの説明に置き換える（#110 は残す）。`docs/reference/usage.md` は、利用者の表示が変わらないため更新を必須にしない。実行手順は `.pi/skills/verify-project/references/feature-map.md` に #109 節を追加し、#101 節の既知の未解決から 91→92 を外す（#101 の記録としての記述は残し、#109 で解決したことを追記する）。CONTRIBUTING.md の正式チェックの入口は変わらないので更新しない。

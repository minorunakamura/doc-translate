# 初回PDF補正で、所有範囲の本文を翻訳元に残す（#97 改訂）

## 目的

[Issue #97](https://github.com/minorunakamura/doc-translate/issues/97) の再開用 Plan。新しくPDFを処理するとき、Docling が読めた本文・手順が AI の補正案から抜けても、利用者の翻訳入力からは消えないようにする。補正案と抽出結果が違う場合は、**その場所の何を根拠に、どの文字を採ったか**を説明できるようにする。保存済みの本を直す作業ではない。

## 要件・決定事項

| 新しい処理で観測したこと | 翻訳元に採用する内容 |
| --- | --- |
| 所有範囲・出典・読順・役割が分かる本文が補正案にない／途中が欠けている | Docling の読めた範囲を本来の位置・所属に1回残す。末尾追記、別ブロックとの二重収録、QAや退避だけでは不可。 |
| 同じ文字を安全に局所整形できる | 文字、語の境界、数字・URL・記号、順序と回数を壊さない整形だけを採る。 |
| 本文の語区切りだけが違い、同じ位置の原本PDFに明確な裏付けがある | 原本に裏付けられる区切りを採る。AI が正しいからではない。両側の文字とその順番を変えず、その局所だけを扱う。 |
| 読める元文字と案が食い違い、許された根拠で読みが決まらない | Docling の文字を翻訳に使い、該当箇所・両者の違いを既存の位置付きQAに残す。たとえば 100→180 は 100。行末に印刷されたハイフンだけでは、行をつないだ後にも必要とはいえない。正しく復元できたとは数えない。 |
| 所有・所属が特定できない／元から不読 | 所有を推測して文字を移さない。読めた範囲は保持し、判定不能の部分は既存の未解決・失敗経路へ。創作も「空白ページ」扱いもしない。 |

**旧 Plan から変える点**：[元の共通 Plan](pdf-initial-source-preservation.md)（SHA-256: `2ed173321bfa12e890499f48eea593863482eb65e502dede7a1e79ec9bb4f798`）の「正常対照」を、#97 では保存済み AI 補正結果との無条件の全文一致としない。残っていた各ブロックについて **内容・役割・構造・出典範囲・相対順・出現回数** を守る。文字差は一つずつ上表で説明し、変更箇所以外は一致を求める。IDの振り直しや間に欠落分が戻ることと、元ブロックの移動・重複を区別する。元の指紋・固定期待を書き換えず、不一致を消さない。差があるブロック全体を比較から外さない。

この判断と、裏付けを得るために**原本の局所テキストを読むこと**はユーザー確認済み。#97 については本改訂を優先する。元 Plan と #98〜#101 の本文・依存関係・承認は変更しない。#101 の統合照合では #97 の差分と未解決を識別して引き継ぐ。#101 が参照する旧期待と衝突する場合はその作業の既存の確認・再計画経路で扱い、ここで統合受入れを改訂・承認したことにしない。

## 原因と判断の根拠

- 調査時 main は `591086c`。コミット版 `pdf_correction._validate_answer` は所有ページの結果と個別の根拠を検証するが、同ページの読める本文が全部残ったかは検証せず、`_make_chunk` が回答を採用する。後段の `assemble_pdf_source` と units は失われた内容を取り戻せない。
- `work/issue83-survey-xcP1KLJ7/root-final/{fixed-expectations,missing-content-gold,hashes}.json` と同親の `root-survey/seed-76/`、`work/design-and-build-great-web-apis/` の保存原本・draft・補正記録を照合に使う。76–80の欠落50項目は補正入力まで届いたが、旧回答・採用は9ブロック（リスト4・本文2・コード3）。欠落には見出し、脚注、コードおよびページをまたぐ項目もある。
- `work/test-verification-97-rP1KZq19/normal-control-check.json` の2件について、元の抽出・保存chunk・対照の対応を読取専用で再確認した。両方とも単一所有span全体で、Docling の orig と text は同じ。保存英文にだけ英数字間の1文字（ハイフン／空白）がある。ref・旧指紋・AI の主張は文字の正しさを示さない。
- hash 照合した原本による局所 Probe：78ページは同じ行の別の語で、対応する範囲を PDFium で読むと両側の文字の間に SPACE がある。76ページは行末のハイフンと次行の続きで、通常の語中のハイフンとは確認できない。これは計画の根拠で、改修後の成功ではない。ページや語を分岐に使わない。

## 制約・対象外

- 既存の dirty 差分・未追跡ファイル・旧 Workspace・旧 attempt・原本・固定期待・marker を保持する。勝手な reset／stash／破棄／commit、旧成功の書換え・再送・移行・翻訳し直しをしない。実AI・追加 retry・新OCR・モデル取得・認証変更・無断 install／共有環境変更なし。trial 15 の停止と累計15 trial／140予約に触れない。
- ページ番号、書名、特定句・ref、期待値、正解 hash、検証用の対応表を製品規則やモデル入力に渡さない。所有ページを実データの位置として使うことと番号で例外化することは別。一般の校正・数値の訂正、全文のPDF再抽出や文字層への丸投げ、新しいレイアウト取得基盤、コード整形・表の再構築（#98）、跨ページの新規接続（#99・#100）、全冊統合（#101）、EPUB の動作変更は対象外。

## 実装方針

1. 再開時に作業ツリーを再確認する。部分実装の `src/doc_translate/pdf_adoption.py` は読順と単一 body を扱うが、page+ref の一致だけで部分範囲・複数根拠・非bodyの役割までは保証できない。`pdf_correction.py` の検証済み回答から採用chunkを作る共通箇所で、保存rawの読順、所有provenance／有効span、ブロック・セル・除外等の所属を照合する。共有refの一部の存在で他の部分を「既にある」とせず、読めた項目を元の位置に統合する。参照のみのページや図内文字を本文に再収録せず、図・欄外への誤分類で本文を隠さない。全体を一方の出力で置換しない。
2. 原本照合は**所有が確定した通常本文で語区切りの採否に必要な局所だけ**。draft が指す原本の hash を検証し、その同じ byte 列を読取に使う。結果を所有ページ、provenance の範囲・座標系に結び付ける。前後の文字列・位置・同一行の語境界を一意に対応付け、同じ位置の文字層で裏付けられる区切りのみ許す。他ページの一致、座標の間隔だけ、任意の全空白除去、編集距離、英数字間というだけでは不可。数値・URL・コード・識別子内の改変に拡張しない。文字層なし・候補複数・行またぎ等は元文字＋位置QA。元資料の hash 不正・方式不明等の検証エラーを「読めない」扱いで受理しない。
3. 現在 lock／PDF環境にある `pypdfium2==5.14.0` を `pyproject.toml` の標準依存に明記し、規約に沿って `uv.lock` を整合させる（ユーザー確認済み）。新方式は基本環境の fresh load でも同じ根拠を再現し、PATH 上の外部コマンド、Docling の起動、環境で結果が変わる fallback に依存しない。EPUB・旧方式では原本の局所読取を起動しない。PDFium は thread-safe でないため、新しい native 操作の open／読取／close が同一プロセスで重ならないようにする。全補正や推論の並列性を止めず、不要な全ページ走査・永続索引・新サービスを足さない。
4. 新規・保存成功再利用・orphan回収・fresh load の全てで、記録された規則を元の入力／回答と結び、同じ採用結果を再現する。旧規則は旧 byte のまま厳密再読し、新規則と取り違えない。規則の有無だけでなく値を厳密に照合し、部分実装の `owned-text-v1` と意味の違う規則を同じ値に割り当てない。未知の識別子・改変・再構成不一致は拒否。検証を緩めたfallbackは作らない。`pdf_source.py`、`revise.py` 等の既存consumerを維持する。
5. `docs/reference/artifacts.md` に採否・原本根拠・旧版再読、`docs/reference/usage.md` にページ処理済みと位置付き要確認の違いを記載。`CONTRIBUTING.md` の依存・license／native条件・検査案内を必要範囲で整合させ、実行手順は下記の既存検証Skillに置く。

## 完了条件

- 75境界を含む所有範囲で、欠落50項目の所有部分を取り戻し、隣接所有chunkとの合計でも原本順、必要回数、役割、連続性が合う。翻訳対象は実際の units、非翻訳部分は英語出力で確認する。「QAに残した」「ページ数が合う」「常にchunkを失敗させた」は不合格。
- 既存9件を1件ずつ対応付ける。失われたり増えたりしたものがなく、本文・リスト構造・コードの全文と改行・出典・相対順を保つ。78の空白は原本根拠により残す。76の行末ハイフンは論理的な語中に必要との裏付けがないので Docling の読みにして位置付きQA。差と残る不確実性を記録し、その他の説明不能な変更は不合格。周辺の脚注・除外、79のJSON・80の数値等も守る。書籍の結果だけで一般性を合格にしない。
- 自作文書でも原本の裏付けの有無で採否が変わる。100→180 は位置付きQAと翻訳元の100が両方必要。新方式の保存／再読、旧成功の無送信・byte不変、方式取り違え／改変拒否、現差分での正式チェック・適用されるReview（人間Code Reviewを含む）・後始末まで確認する。

## 動作確認方法

- **TDD は採用と保存再読の契約だけ**。既存 `tdd` Skill を使い、自作PDF・人工回答で公開 `correct_pdf → load_pdf_correction → assemble_pdf_source → generate_translation_units` を通す。既存の欠落・数値・旧byteテストを生かし、原本に区切りがある／ない・曖昧の代表を語句や位置を変えて確認。局所照合の有無を結果で見分ける反例を先に失敗させる。既に緑の部分を壊してRedを作らない。実書籍・文書・配布・統合操作は非TDD。新たな全経路E2E・CIや全PDF品質の保証は足さない。
- **実資料は読取専用の無送信再生**。既存 verify-project の「PDF原文標本準備」「PDF run／resumeの工程・所有ページ進捗」「保存記録と詳細検査」を再利用する（`.pi/skills/verify-project/SKILL.md` と `references/feature-map.md`）。新規0700親の隔離先へ必要な入力を準備し、保存回答を新しい採用→保存→別processのload→units／英語renderへ通す。正解は比較側のみ。Root が原画像・50項目・9件の対応、各差の両側文字／根拠／QA、翻訳対象との対応を直接照合する。許可された資料だけを扱い、書籍本文・画像・生回答をstdout、Git、Issueに出さない。
- **通常経路は別に**、自作PDF・既存実Node/faux/no-networkで run→fresh resume。欠落を含む回答からの翻訳入力、無変更時の再送ゼロ、旧成功の保持を確認する。既存並列条件でも原本照合の結果が直列と食い違わず、他のjobの資料を参照しないことを限定確認する。実AIでの意味品質検証ではない。
- Worker は focused 回帰と手順の再実行、Root は別の隔離先で直接操作し全受入条件を判定する。書籍再生と局所比較の手順は現資産に不足するため、Implementation で共通 `create-verification-skill` により既存Skill／Mapの関係節と必要最小のhelperだけを補う。Root は範囲・期待を維持したまま現在の手段を再確認・具体化できる。版・dirty差分・入力hash・コマンド／exit・期待と観測・差と未確認を private に記録し、自分の一時物とchildだけを回収。元hash／mtime・markerと残す証拠を再読する。
- `CONTRIBUTING.md` の正式チェック・PDF補正／組立・wheel・依存更新節に従う。focused は補正・組立・units／英語render・run/resume・候補採用の影響consumer。標準依存と保存境界を変更するためcore全pytest、正式PDF phase、Ruff check／format・PDF環境ty、lock・配布物の依存metadata／license・core利用を確認。必要な別環境導入検査が未許可なら無断実行しない。過去の成功やCode Review Approveは流用しない。手段不足なら試した方法／実際の不足／再開条件を示して BLOCKED。制約・保証・設計を変える必要があれば REPLAN_REQUIRED。

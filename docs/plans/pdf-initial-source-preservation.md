# 通常のPDF初回補正で、読み取れた本文を落とさず構造を改善する

## 目的
新しくPDFを処理する利用者のための修正。Doclingが読み取った本文・手順を翻訳入力に残し、原文の内容・構造が翻訳対象または英語出力まで届くことを検査する。扱うのは①初回補正での本文脱落、②コード・表の局所構造、③ページ間の接続候補と独立した図・脚注・リストの保持。全件を一つの採用規則で自動修正できるとはしない。過去の訳文を修復する計画ではない。対象は minorunakamura/doc-translate の main（調査時 591086c）。旧 #84・#88〜#96 は not planned。旧実験ブランチやその未マージ実装は前提にしない。

## 要件・決定事項
- 所有ページの安全に読める文字・数値についてはDoclingを基準とする。AIが「100」を「180」と読んでも「100」を翻訳元に残し、位置と相違を既存QAで要確認にする。画像に見えるというAIの主張だけで置換しない。単なるrefの存在、ページ単位の回答、raw/退避領域への保存では本文保持と数えない。
- AI回答はページ全体の置換ではなく、根拠のある局所の構造・整形に使う。語中空白、数字、URL、記号、順序、出現回数を壊さない。複数断片を一項目にまとめることと、途中を削って同じrefを付けることを区別する。画像だけの領域や局所不読を空白ページや解決済みとみなさず、根拠のない原文を生成しない。
- 出典と役割を保つ。本文・手順を図内部、繰返し装飾、除外等に誤分類して隠さず、正当な図内部や欄外を一律に本文へ重複採用しない。解決できない相違は既存uncertainty/QAで識別し、読み取れた本文は翻訳元に残す。安全に所有を証明できない範囲は推測せず既存の未解決・失敗経路へ。警告を出しただけで欠落防止成功としない。

## 確認した原因・照合資料
- main の `src/doc_translate/pdf_correction.py`：`_projection` が許可ページを根拠範囲付きで投影し、`_validate_answer` は所有ページ集合と個別根拠・構造を検証する。ページ内の読める本文が採用内容に残ったことは検証せず、`_make_chunk` は回答ブロックを採用する。`pdf_source.assemble_pdf_source`→units は採用原文を使う。翻訳で取り戻すことはできない。
- `work/design-and-build-great-web-apis/` の原本・Docling raw・初回補正request/answer/chunkと、`work/issue83-survey-xcP1KLJ7/root-final/{fixed-expectations,missing-content-gold,code-gold,hashes}.json`、同親の `root-survey/seed-{76,111,346}/` の対応・原画像を参照。76–80の欠落50項目は参照/所有境界の分割を含め補正入力まで届いていたが、回答と採用本文は同じ9ブロック。逆に115–116のコードでは、構造補正後の断片は41行と字下げが原本通りで、346の表は補正で6行×2列の所属を復元できた。これは保存回答の観測で、改修後の実測ではない。

## 制約・対象外
過去のWorkspace・訳文の修復/移行・再翻訳はしない。原本、旧attempt、失敗、trial 15 の安全停止、累計15 trial／140予約は読取専用。追加実AI送信、再試行、認証・marker変更、新たなOCR・install・共有環境変更なし。正解・ページ番号・特定ref・書籍専用文字列を採否ロジックやモデルに渡さない。EPUB、別件のrender誤警報、翻訳品質、新CLI、新DB、後段の修復runner、全冊評価は対象外。今回の構造保持を理由に曖昧なページ境界を自動で結合しない。

## 実装方針
1. 初回補正の採用時に、保存済みDocling原資料の読順・所有ページの範囲とAIブロック/セルの位置根拠を対応付ける。`_projection` のref辞書順を読順にしない。参照専用ページ、重複provenance、跨ページspan、範囲不正、図内部・caption・脚注を区別する。基準本文は一回だけ使用し、欠けた段落を末尾へ足すのではなく元の順序・所属に残す。読順や境界が一意でない場合は、断定した構造へ置換しない。
2. `correct_pdf` の回答・根拠の既存検証を保持し、検証済み回答から採用chunkを作る共通箇所で局所的に適用する。元文字列から一意に説明できる整形だけを採用する。コードは文字トークンと行境界/字下げ、表はセル内容と範囲・行列・所属を別々に照合。全空白除去や文字集合・件数だけの一致を根拠にしない。文字差・省略・競合は元内容を保ち、既存の場所付きQAへ。body以外のセル・構造・unitsにも同じ決定を反映し、raw回答や履歴を事後変更しない。許可済みページの意味上の漏れに再送を追加しない。
3. **接続を扱う場合は、初回補正の採用と別の組立判断にする。** 新方式のsourceのみに、owned fragmentの元の提案を相互照合した適合組が双方で一意な場合の接続を適用する。候補の絞込み前にraw evidenceが複数というだけで正当な組を捨てない。既存のdraft-local ref/異draft identity、mode、構造、読み順を緩めない。図を挟む本文では同一raw内の順序・spanの間に他の本文がないこと、介在する独立図を元の位置・所属で残せることも必要。結合で生じる参照・callout行・QAの対応は既存処理を再利用する。いずれかの端に複数の適合相手、片側の誤targetや未証明の飛越しがあれば結合せず両fragmentと未解決記録を保持する。判定に固定正解を使わない。
4. **新規採用と旧版の再読を分ける。** 保存要求に採用規則の識別を明示し、入力/回答と結び付ける。既存のrequest契約・immutable照合を再利用し、新規生成、orphan回収、`_saved_correction`、`load_pdf_correction` が同じ方式で再現すること。旧記録は旧規則で厳密に再読し、新規則の根拠にはしない。既存run/resumeの旧成功からの再開・旧原文照合・候補採用は旧byteを保ち、規則追加だけで再送しない。新しい通常runに新規則を適用する。旧検証を緩めるfallbackや移行ツールは作らない。
4. `docs/reference/artifacts.md` に初回補正の採否・根拠・旧記録との関係、`docs/reference/usage.md` に「ページ処理済み」と本文の要確認の違いを記す。再実行手順は `.pi/skills/verify-project/` の関係節・Feature Map、開発チェックの入口は必要時のみ CONTRIBUTING.md に置く。旧評価Planは書き換えない。

## 完了条件
- 同じ初回補正の製品経路を用いて、以下の本文・コード・表を同時に守る。76–80と境界75の公開原文を別processで再読し、画像確認済み50項目の**所有範囲分**および隣接所有chunkを含む全項目が原本順・必要回数・所属・連続性を保ち、翻訳対象となる部分は実際のunits、非翻訳で出る部分は英語出力に届くこと。参照のみのページを取り込まず、数字や箇条書きを消さない。欠けたままQAに置く、chunk全体を常に失敗させる、原文全体をAI/Doclingの片方に丸投げする方法は不合格。
- 同じ規則で115–116のコードが順番通り41行、各行全文・字下げを保持し、346の6×2表は全12セルの内容と行列・URL・数値が一致する。断片内の品質と別個の跨ページ結合の成功を混同しない。119–121で既存AIが誤った字下げを出した21行を「完全復元」と報告しない。人工の文字相違例ではDocling値を保存・出力し、QAに位置と相違が残る。
- 新方式の再読・再利用と旧方式の再読が成立し、改変記録や方式の取り違えを厳密に拒否する。通常経路、最新差分の正式チェック、人間Code Reviewを含む適用対象Review、保全と後片付けまで確認する。

- **接続の受入れは最終出力で判断する。** 候補一意の8組は同じ新方式の隔離実行で、二重・脱落なし、独立図・脚注・caption/周辺段落・旧版保持を原画像と照合。コード接続と字下げを別々に採点し、119–121を総合成功にしない。負例は一方に適合相手が2件以上ある自作例・誤target・途中本文、実画像と固定期待に照らす正常対照を使う。全書籍で新たに変わる組について旧／新出力差を無送信で列挙し、意図しない結合を原画像との照合なしに承認しない。旧記録を変更せず新方式で検証できない場合は根拠と不足を報告する。#65のrender誤警報・EPUB等の別件は今回の成果に含めない。

## 動作確認方法
- **TDD** は採用規則、公開assembleの相互一意/拒否、および保存再読の分岐に限定する。既存tdd Skillで公開 `correct_pdf → load_pdf_correction → assemble_pdf_source` に小さい自己作成fixtureを通し、同一ページの途中の段落が消える現行の失敗を先に確認。文字差/構造だけの差、旧成功/不正再読は該当する契約を少数の回帰で押さえる。実書籍照合、ドキュメント、統合操作は非TDD。全組合せE2Eや新CIは作らない。
- 実資料は旧Workspaceを新方式で開き直すテストではない。隔離した新規0700親に公開readerで必要な入力を読み、保存済みの初回回答内容を**再生**して新しい採用経路→保存→fresh load→units/英語renderへ通す。旧runを新規成功として書き換えず、実AIの再現性の証明とは数えない。正解は結果照合側だけ。原本画像と期待をRootが直接照合し、件数だけでなく順・対応・重複・局所不読と周辺の正常領域も確認する。書籍本文・画像・生回答はprivateのみ、Issueや通常stdoutには出さない。
- 別に通常run/resumeを既存の自作PDF fixture・実Node/faux/no-networkで操作し、部分欠落回答でも本文が翻訳入力にあること、差異のQA、無変更resumeで成功済みを再送しないこと、旧Workspace再読を確認。実書籍全翻訳や実provider起動は行わない。
- 検証資産は verify-project の「PDF原文標本準備」「PDF run／resumeの工程・所有ページ進捗」「保存記録と詳細検査」を再利用する。新方式/保存回答の安全な再生と本文対照は未整備なので、共通 create-verification-skill で関係手順と必要最小のhelperのみ補う。Workerは限定実装・focused回帰・手順再実行。Rootは異なる隔離先で直接操作し、版・入力/元hash・コマンド/exit・比較結果・失敗も記録。作成した一時ファイルとchildのみcleanupし元hash/mtime、marker、保持証拠を再確認する。
- CONTRIBUTING.mdの影響選定に従い tests/test_pdf_correction.py、test_pdf_source.py、test_run.py、test_resume.py、test_pdf_candidate_acceptance.py、units/renderの関係consumerと専用helper、Ruff check/format・PDF環境tyを確認。共有fixtureや共通保存に影響する場合はcore全pytest・PDF正式phaseに拡大。Implementation Rootは上記保証を変えない隔離手段と小さいhelperを具体化できる。必須部品/権限不足で安全に成立しなければ理由と再開条件付きBLOCKED。仕様・保証の変更はREPLAN_REQUIRED。実装・commit・公開は本Planの提出では開始しない。

## 要件・決定事項
第5版の要件1・2（既知の未解決2組と、別 Issue）をすべて維持する。そのうえで次を決める。

1. **対応表の単位（関数＋採用側の分岐）。** 対応表には、次をそれぞれ1行ずつ載せる。
   - #101 で追加した製品の関数。
   - 採用結果を変える正の分岐（採用側の分岐）。少なくとも if:1327・if:1512・if:2947 を含む。
   - 不変条件の検査（`covered`）。

   各行には、それを必要とするテスト（無効にすると失敗するテスト名）か、下の要件2の扱いとその根拠を書く。拒否の条件（拒否して chunk 全体を保存しない側の分岐）は1つずつは載せない。「安全側の拒否」として件数とまとめて記録する。
2. **テストのないコードの扱い（種類ごと）。**
   - **実書籍で必要な採用側の分岐（if:2947）：** テストを足して残す。
   - **実書籍でも結果が同じ採用側の分岐（if:1327、if:1512）：** 削除する。削除は分岐だけに限り、ほかの規則は変えない。
   - **不変条件の検査（`covered`）：** 残す。公開入力からは起こせない、文字の所有を守る検査である。残す理由を対応表に書く。
   - **拒否の条件（44個を含む）：** 残す。削除もテストの追加もしない。
   - Implementation で、上の3つ以外にも全テストが必要としない採用側の分岐が見つかることがある。その場合も同じ規則で扱う。書籍での結果が変わるならテストを足し、変わらないなら削除する。拒否の条件か採用側の分岐かの判断に迷う場合は、対応表で理由を示す。
   - 削除した結果、全70件の再生で保存数・採用結果・接続差分が第4版の結果（診断用）と違ってきた場合は、その分岐を「実書籍で必要」とみなす。削除を取り消して、テストを足す。
3. **テストの追加方法（特性テスト・TDD ではない）。** 対象は if:2947 と、要件2でテストを足すことになった分岐。小さい自作PDFを使い、公開の `correct_pdf → load_pdf_correction → assemble_pdf_source` で検証する（`tests/test_pdf_correction.py`）。
   - **Red：** 隔離したコピーの src で、その分岐だけを無効にする。新しいテストが失敗することを確認する（第5版の `mutate.py` の方式でよい）。
   - **Green：** 現在のコードで成功させる。
   - 書籍固有の文字列・ref・ページ番号・固定座標は、テストの入力にも期待にも使わない（第4版どおり）。
